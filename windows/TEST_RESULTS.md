# Windows 接收端驗證紀錄

最後更新：2026-11-05

## 自動測試

`python -B -m unittest discover -v`：2026-11-05 最新 **53 項通過**。涵蓋接收／ACK、六參數模式、OSC 編碼、tracker 角色 ID、離線座標校正、品質統計、極端數值、時間順序、32 組相機座標變換與測試工具提前停止。新增測試重現鏡像模型標籤反轉，確認明確左右對調後符合真人角色及 yaw，且不修改收到的封包。

本輪原有 closed UDP peer 整合測試兩次未收到 Windows ICMP 重設通知；通知是否回報受 OS／防火牆影響。整合測試仍確認後續真 UDP 封包與 ACK 可用，另新增可控的 `ConnectionResetError` 測試，確保重設分支被計數且接收不中斷。沒有修改 receiver 的重設處理程式。這些是本機自動測試；VRChat 的 OSC FBT 遠端盲測另見 [Phase 0 證據](../VIRTUAL_HMD_PHASE0_PLAN.md)。

收尾重跑另曾遇到多個 `bind(("127.0.0.1", 0))` 被 Windows 回報 `WinError 10013`，提高執行權限也曾發生；同時固定本機埠仍可綁定。之後單獨 UDP 測試、匯入全部測試後綁定與最後一次完整 53 項均通過。沒有變更防火牆、系統埠範圍或排除清單；這個環境間歇狀況仍待查，不能聲稱已修復。

## 實測髖高與語音時間標記複驗（2026-11-05）

使用者量得左／右站姿髖高各 **90 cm**，採平均 **0.90 m**。以電腦中文語音提示並為每段動作標記本機單調時間，動作期間不要求打字，結束後一次確認。全程不建立 OSC 輸出，不保存原始影像或 landmarks。

第一輪未對調標籤時，語音要求真人右腳抬起卻出現 `left_foot.y` 中位數 0.370 m；要求左腳時 `right_foot.y` 為 0.303 m。使用者確認依自己的左右腳做動作。因此**撤回早期未同步手動觀察的「左右已通過」結論**。

加入明確 `swap_left_right` 後，只複驗受影響的左右腳、向右轉及回正。此支 `SM_A5360` 前鏡頭設定為 `--hip-height 0.90 --mirror yes --swap-left-right --forward-sign -1 --yaw 0`。使用者確認整輪均按提示完成。以下為各段排除開頭 1 秒、末尾 0.5 秒後，約 4 Hz 顯示樣本的中位數；不是全部輸入影格或外部真值：

| 語音動作 | 左腳 y（m） | 右腳 y（m） | 髖 yaw（度） |
| --- | ---: | ---: | ---: |
| 站立 | 0.099 | 0.139 | +0.2 |
| 真人右腳抬起 | 0.086 | 0.335 | +3.5 |
| 真人左腳抬起 | 0.349 | 0.087 | -0.5 |
| 向右轉 | 0.096 | 0.064 | +30.9 |
| 回正 | 0.093 | 0.141 | -1.7 |

右腳放下後回到約 0.134 m，左腳放下後回到約 0.093 m，支持修正後的左右角色與轉向。站立髖 y 中位數 0.905 m，但這部分使用輸入髖高定尺度，**不能當作獨立精度驗證**。實際抬腳高度及轉身角度未用外部量尺量測；腳部地面偏移、左右站姿高度差與動作幅度精度仍待查。

修正後整輪接受 2,321 幀，產生 1,866 組完整 transforms（80.40%，包含就位及校正），一次校正、零次失追。首次穩定已校正快照為 510 幀／55 組 transforms；此後至結束增加 1,811／1,811，拒絕計數未再增加。這些為影格計數，不是有效時間比例或十分鐘驗收。第一輪語音測試另觀察到蹲下的相對髖高下降，沒有重做此動作；手機仍未接到 VRChat FBT，HMD 絕對 yaw 與遠端同步尚未驗證。

## 單手機離線 tracker 預覽（2026-11-05）

以下保留早期手動觀察數據。當時動作與終端機資料未同步，左右角色及 yaw 正負的結論已由上面的語音複驗取代。

手機 `SM_A5360` 的 App `0.1.0` 經電腦私人熱點把 MediaPipe landmarks 送到 `tracker_preview.py`；測試設定為鏡像 `yes`、前向符號 `1`、初始 yaw `0°`。站姿髖高 **0.89 m 為暫估值，未量測**。工具只顯示推算 transform，沒有建立 OSC 輸出，也沒有保存原始影像或 landmarks。測試期間有封包到達且完成站姿校正；在約 300 秒的狀態快照中，已接受 5,210 個封包、schema 錯誤與序號缺口均為 0、`osc_updates=0`。這不是最後全程計數，也不是長時間穩定性驗收。

依照當場的動作指示，終端機觀察到：

1. 當時輸出曾顯示 `right_foot.y` 約 `0.06 → 0.18 m`、`left_foot.y` 約 `0.09 → 0.50 m`。因沒有可靠對齊真人動作時間，不再視為左右映射證據；動作公尺幅度也未獨立量測。
2. 蹲下時髖的推算高度約 `0.95 → 0.30 m`，雙腳仍約 `0.05–0.12 m`；支持地面與髖高度的相對變化。
3. 向使用者右手方向轉身、再轉回時，髖 yaw 約 `0° → -55° → 0°`。這只驗證相對轉向；與虛擬 HMD 的絕對 yaw 對齊未驗證。

過程中曾有 `PREVIEW_LOST` 並重新校正；腳部 yaw 在蹲下和腳部動作時波動。這些早期資料**不能**當作穩定 tracker 輸出、VRChat FBT 或遠端同步已通過；後續已量髖高並完成上述語音複驗。
