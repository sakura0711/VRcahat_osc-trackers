# 已存 ZIP 的三姿勢 tracker 回放

`tracker_replay.py` 從原始 ZIP 的手機 landmarks 建立一次站姿校正，再重複輸出三個固定姿勢：**站姿 → 真人右腳上箱 → 放回**。預設只列出計畫，不建立 socket。手機 App 不需更新、啟動或傳送，也不需 USB、熱點或 ACK。

這是探索目前位置估計對 VRChat IK 的視覺影響。照片約每 3 秒一張；工具不補中間影格、不放大高度，不能用來驗證即時延遲、動作平順度、遮擋／失追或十分鐘穩定性。使用來源為手機原始 Lite landmarks，沒有換 Full。正式 250 ms 失追策略與 receiver 均未更動。

## 先檢查，不送 OSC

在 `windows` 目錄執行：

~~~powershell
$replayArgs = @(
  'captures/right-box-images-20261106/source.zip',
  '--calibration-frames', '3-7',
  '--stand-frame', '4', '--box-frame', '11', '--return-frame', '18',
  '--hip-height', '0.90', '--mirror', 'yes', '--swap-left-right',
  '--forward-sign', '-1', '--yaw', '0',
  '--expect-sha256', 'da27054e6dab99f031cb5cc4f897bde61a180f8f599d1cf6f4978c0795645d2c'
)
python -B tracker_replay.py @replayArgs
~~~

應看到 `REPLAY_PREPARED` 與 `INSPECTION_ONLY`。可加 `--report captures/new-replay-plan.json` 保存計畫；檔案必須不存在。照片、ZIP 與詳細計畫留在 Git 忽略的 `captures`。

工具驗證原 ZIP 雜湊、配對身份、PNG、明確鏡像與角色設定、站姿校正、全部三個完整 transforms 與數值邊界；任一選定姿勢失敗即拒絕整輪，不挪用上一幀。稀疏照片的校正使用來源時間，限於本工具採 0 秒／5 樣本／5000 ms 間隔與超時；不是宣稱即時追蹤通過。

預設 `--rotations standing` 將三段的髖／腳旋轉固定為首個站姿的值，位置仍是各選定影格的原估計。這先隔離位置對 IK 的影響，不代表腳部轉向已驗收。另有 `--rotations recorded` 可重放各影格估計的 yaw，應另作有記錄的實驗。兩者皆保留原校正與位置幅度；pitch／roll 仍為零。`--yaw` 只明確旋轉校正座標，不會自動量得虛擬 HMD 的朝向。

## 等使用者就位後，才啟用 OSC

1. **先播放語音通知需要協助測試，等使用者回覆已就位。** 不要求真人重做箱面動作，只需看 VRChat 鏡子。準備同一未修改 Avatar、VR 模式與 AnyaDance HMD／雙控制器；AnyaDance 自帶 trackers 保持停用。不要重做 Phase 0 的遠端盲測或 `-202` 顯示診斷。
2. 確認 OSC 輸入埠、沒有其他發送器與當次 FBT 的髖／左右腳 ID。上次是 1／4／3，但不是永久規則。只有明確加 `--osc --hip-id H --left-foot-id L --right-foot-id R` 才建立輸出；H／L／R 必須換成確認的相異 1–8 整數。OSC 模式還必須提供正確的 `--expect-sha256`。目的地固定 `127.0.0.1`，預設 UDP 9000。
3. 啟用後先以預設 20 Hz **只維持站姿**，供檢查對齊與必要的 FBT 校正。尚未開始右腳回放。若重新校正後角色不符，先停止並更正 ID。確認站姿、身體朝向與角色後，再語音提醒即將開始。
4. 在回放器的標準輸入送一行 `play`。依序各保持 8 秒，共 24 秒後自動結束；`stand` 中斷序列、回到站姿等待；`quit`／Ctrl+C 停止。啟用起預設最多 180 秒（可設 1–600 秒），即使一直等待也會停止。終端機關閉／標準輸入 EOF 也會停止；明顯執行停頓後不接續過期的抬腳段。
5. 記錄自己的觀察：動的是哪隻腳、增量能否看清、是否穿地／膝反折／身體歪斜、放回是否合理。先驗本機視覺影響；UDP 送出本身不能證明遊戲接收、IK 正確或遠端同步。

停止時會盡力送一次已驗證的首個站姿，再關閉 socket。**停止送出不保證 VRChat 立即清除最後一個 tracker 姿勢**；異常時以遊戲本身的 OSC／FBT 控制恢復。中途終止、傳輸錯誤或程序被強制結束不能保證最後站姿成功送達。若需要更長時間觀察，另起一次明確實驗，不背景無限循環。

## 本批準備結果與限制

來源 captureSession 為 `d9173e82-db7d-4223-b2c9-46123c35dc69`。第 3–7 張建立尺度 1.0492527566；代表影格為第 4／11／18 張，frameId `109449710`／`109470905`／`109492061`。沿用前鏡頭、髖高 0.90 m、mirror=true、swap=true、forward=-1、yaw=0 的已記錄設定。

| 選定姿勢 | 髖 y（cm） | 左踝 y（cm） | 右踝 y（cm） |
| --- | ---: | ---: | ---: |
| 站姿 | 89.70 | 8.31 | 10.64 |
| 真人右腳上 20 cm 箱面 | 89.52 | 8.35 | 17.18 |
| 放回 | 90.54 | 8.79 | 11.06 |

這三張的右踝增量為 6.54／6.12 cm；和先前整段中位數的約 5.1 cm 是不同統計，並非算法改善。左腳與水平位置也有估計變化，並未只改右腳 y；因此遊戲中可能同時出現左右／深度位移。完整精度留在本機計畫。公尺精度、HMD 絕對對齊、本機 IK 與遠端效果仍待驗證。

`python -B -m unittest discover -v`：完整 **95 項通過**，含回放器新增 11 項檢查。後續站姿模式下用單一連續發送程序進行合成、放大及原始 ZIP 三輪；使用者回報三輪正常，明確確認原始 ZIP 與放大版均是角色自己的右腳，且原始抬腳清楚可見。未達 20 cm 對本次抬腳視覺可見性由使用者評估為低風險；公尺精度、其他動作、即時輸入與遠端同步仍待驗證。[完整紀錄](TEST_RESULTS.md) 也保留此前坐姿錯誤／模型不動的結果。
