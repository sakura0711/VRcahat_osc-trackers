## 固定校正的離線幾何計算

依照片姿勢分段，不以手機時鐘減 Windows 語音時鐘：前站姿第 **3–7** 張、箱面第 **10–15** 張、後站姿第 **17–21** 張。排除走位、低頭／初步上箱及動作邊界。16 張選定照片均通過現有來源品質／幾何檢查。

用第 3–7 張的五個站姿樣本建立一次校正，再對各選定照片呼叫現有 `_frame`／`_transforms` 做純離線幾何比較。設定為髖高 0.90 m、mirror=true、swap=true、forward=-1、yaw=0；尺度 **1.0492527566**，上軸 `(0.022075, -0.972696, -0.231029)`。這個上軸不是實測手機俯仰角。

**3 秒照片不能驗證 250 ms 的正式失追策略。** 為取樣幾何診斷，僅在臨時離線設定採 `calibration_seconds=0`、`minimum_samples=5`、間隔／超時 5000 ms；正式程式預設完全未改。沒有同輪 UDP 紀錄，因此未把舊 JSONL 連到這些照片，也未宣稱即時校正或連線驗收。

## 已證實與待驗證的邊界

已證實真手機擷取／保存／ZIP 匯出與 Windows 匯入可用；完整影像可核對動作，且來源幾何低估再次出現。代表點位能辨識右腳上箱，但有局部 2D 偏差。這些不能替代獨立關節高度、像素定位或公尺尺度驗收，也不能把本輪約 5.1 cm 與舊輪約 6.9–7.8 cm 的差異當作演算法退步／改善：算法未改、取樣與姿勢不同。

透視仍待量化：影像沒有鏡頭內參、實測相機俯仰、各幀腳部深度或腳部角度。可見像素上升不能直接換成 20 cm；目前不能把主要原因指定為透視、2D 定位、3D 推論或 lite 模型其中之一。下一步先利用固定 PNG 補獨立腳點／箱面參考與投影一致性分析，再決定需要哪一種模型或校正實驗；不直接放大高度。

CPU／GPU delegate 未記入封包，本次沒有建立 GPU 證據；保存負載、背景停止、長時間運作亦未完成實機驗收。瀏覽器自動檢視因工具無法確認目前網址而中止；改以原始 PNG 與本機科學繪圖核對，未宣稱瀏覽器互動實測通過。

此前嘗試同時連 UDP 的 receiver 收到 **0 封包**，ACK 原因未解決；之後明確改為純本機影像測試，不開 receiver、不需要 ACK。純照片成功不代表網路已修復。離線分析以建立 socket 即失敗的 guard 執行，手機 OSC 為 **0**；不涉及 FBT、遠端同步、SteamVR 或 Unity 驗收。
